# Задача: встроить дизайн v3 в модуль ModuleMessengerHub (MikoPBX)

Ты работаешь в репозитории модуля **ModuleMessengerHub** для АТС MikoPBX. Модуль уже работает: вкладки «Уведомления», «Журнал», «Настройки», мастер «Новое уведомление» из трёх шагов, боты Telegram и MAX. Логику не переписываем — меняем вид, тексты и несколько правил показа, чтобы интерфейс совпал с макетами.

## Входные файлы (положи их в репозиторий, например в `docs/design/`)

- `ModuleMessengerHub-v3.html` — макеты всех экранов. Это эталон: размеры, порядок элементов, тексты. Открой в браузере и сверяйся с ним.
- `mh-theme.css` — токены (CSS custom properties) и переопределения Fomantic UI, ограниченные корнем `.module-messenger-hub`.

## Технические рамки (обязательно)

- Стек модуля: Volt + jQuery + Fomantic UI. Без React и без новых JS-библиотек.
- Всё оформление — только внутри `.module-messenger-hub`. Шапку страницы MikoPBX (колокольчик, заголовок, «Модуль включен», шестерёнка), боковое меню и остальную админку не трогай.
- Из `mh-theme.css` перенеси в CSS модуля токены и правила для `.module-messenger-hub`. Не переноси классы, нужные только макетам: `.mh-host*`, `.mh-board-note`, `.mh-state-tag` и подключение Inter из Google Fonts (АТС часто без интернета). Шрифт — Inter из файлов модуля, если они есть, иначе системный стек из `--mh-font-sans`.
- Размеры под админку: основной текст 14/20 px, подписи 12/16 px, `letter-spacing: 0`, все кнопки и поля высотой 32 px, ширина колонки формы не больше 560 px.
- Работает на ширине рабочей области от 1024 до 1920 px без горизонтальной прокрутки (кроме широкой таблицы журнала — она в контейнере с `overflow-x: auto`).
- Тексты — через файлы переводов модуля (Messages/ru.php и т. п.), не хардкодом. Старые ключи с убранными подсказками удали.

## Общий принцип

Модуль максимально простой: заголовки, поля, кнопки. **Никаких поясняющих абзацев, инструкций и подсказок под полями.** На каждом экране одна оранжевая (primary) кнопка. Нормальное состояние — тихое (серый текст или зелёная точка), цветная метка — только у проблемы.

## Экраны

### 1. Вкладка «Уведомления»

- **Нет ни одного бота** → по центру заголовок «Подключите мессенджер» и две плитки-кнопки: Telegram и MAX (иконка + название, без описаний). Клик открывает форму бота сразу на выбранном мессенджере.
- **Бот есть, уведомлений нет** → «Уведомлений нет» и primary-кнопка «Новое уведомление».
- **Есть уведомления** → primary-кнопка «Новое уведомление» справа на одной линии с вкладками. Список сгруппирован по категориям: Звонки → ИИ Супервайзер → Голосовой агент → Связь и АТС.
  - Если все уведомления из одной категории — **заголовков секций нет**.
  - Если категорий две и больше — заголовки секций: прописные, 12 px, 600, `letter-spacing: .06em`, полупрозрачные (`--mh-color-text-secondary`), с тонкой линией снизу (`.mh-group-title`).
  - Строка (`.mh-notif-row`): переключатель · иконка мессенджера 20 px · название · справа время последней отправки (серым) или красная метка проблемы («Бот удалён») · кнопка «⋯».
- На вкладке «Журнал» — красный счётчик недоставленных за сегодня, если они есть.

### 2. Мастер «Новое уведомление»

Сверху ссылка «← Уведомления» и заголовок. Индикатор шагов и подзаголовки не нужны.

- **Шаг 1, сценарий.** Заголовок «Новое уведомление». Карточки по тем же категориям, с теми же заголовками секций. Карточка = иконка + название, без описания. Сетка `.mh-scenario-grid` (auto-fill, minmax 260 px) — без пустых мест. Выбранная карточка — оранжевая рамка (`.is-selected`). «Далее» неактивна, пока ничего не выбрано. Снизу: «Отмена» (basic) слева, «Далее» (primary) справа.
- **Шаг 2, условия.** Заголовок — название сценария. Поля без подсказок:
  - «Сотрудники» — dropdown, плейсхолдер «Все». Не показывай «Нет доступных вариантов»: если список не загрузился — `.field.error` и «Повторить», поле остаётся рабочим со значением «Все».
  - «Направление» — сегментированный выбор в одну строку (`.mh-seg`): Входящие / Исходящие / Внутренние.
  - Переключатель «Удалять после перезвона» — без отдельного заголовка над ним.
  - Справа предпросмотр сообщения, без подписи над ним.
  - Снизу: «Назад» (basic) слева, «Далее» (primary) справа.
- **Шаг 3, куда отправить.**
  - «Бот» — плитки подключённых ботов (иконка + имя). Если бот один — выбран сам.
  - «Кому» — радио: «Сотруднику» / «В чаты» / «Сотруднику, иначе в чаты» + выбор чатов.
  - Переключатель «Скрывать номер».
  - Снизу: «Назад» слева, primary «Создать» справа.

### 3. Вкладка «Журнал»

- Если бот удалён или токен не работает — над таблицей одна красная строка `.ui.negative.message`: «Бот @имя удалён — сообщения не доставляются» и кнопка «Подключить». В строках таблицы этот текст не повторяй.
- Фильтры: только «Период» и «Событие».
- Колонки: стрелка · Время · Событие · кратко (серым, в одну строку с многоточием) · Отправка. Отправка: «Доставлено» — зелёная точка с текстом; ошибка — красная метка «Не доставлено». Колонку «Важность» убрать.
- Высота строки ≈ 48 px. Пробные события (`проба`) по умолчанию не показывать; если показываются — маленькая метка `.mh-probe` в той же строке, не отдельной строкой.
- «Клиенту перезвонили» — не отдельная строка журнала, а поле «Перезвонили: 18:44» в раскрытой карточке пропущенного звонка.
- Раскрытая строка: 3–4 поля (Сотрудник, Клиент, Перезвонили, получатели со статусом). Технические поля (тип события, ID звонка, источник) убрать из интерфейса.

### 4. Вкладка «Настройки»

- Секция «МЕССЕНДЖЕРЫ». Ботов нет — две плитки Telegram и MAX, как на первом экране. Боты есть — список ботов (иконка, имя, статус) и primary-кнопка «Подключить мессенджер». Никаких заглушек «скоро» и описаний вроде «Бот создаётся за минуту…».
- Секция «ОБЩИЕ», поля без подсказок: «Адрес АТС», переключатель «Скрывать номера», «Хранить журнал, дней», «Прокси».
- Под полями одна серая строка: «Данные передаются в Telegram и MAX.» Большой оранжевый блок предупреждения убрать.
- Изменения сохраняются сразу (тост «Сохранено»), без кнопки «Сохранить».

## Решение, которое нужно подтвердить у владельца продукта

Переключатель «Модуль включен» в шапке MikoPBX — синий, тумблеры модуля по макету — оранжевые. Сделай цвет тумблеров модуля одной переменной (`--mh-color-brand` для `.ui.toggle.checkbox.checked`), чтобы его можно было переключить на синий `#2185d0` одной строкой.

## Как работать

1. Сначала изучи структуру репозитория: Volt-шаблоны вкладок, JS мастера и журнала, CSS модуля, файлы переводов. Составь короткий план: какой файл что меняет.
2. Подключи CSS-токены, затем переделывай экраны по порядку: Уведомления → мастер → Журнал → Настройки.
3. Логику API и хранения не меняй. Если для правила (например, «перезвонили» внутри пропуска или скрытие пробных) нужны данные, которых нет на фронте, — опиши, что нужно от бэкенда, и не выдумывай.
4. После каждого экрана сравни с `ModuleMessengerHub-v3.html` на ширине 1024 и 1920 px: размеры, порядок, тексты.

## Готово, когда

- [ ] Все экраны выглядят как в `ModuleMessengerHub-v3.html`; лишних текстов и подсказок нет.
- [ ] На каждом экране одна primary-кнопка.
- [ ] Заголовки секций появляются только при двух и более категориях.
- [ ] Первый запуск без бота ведёт к выбору Telegram / MAX.
- [ ] «Далее» на шаге 1 неактивна без выбора; на шаге 2 нет «Нет доступных вариантов».
- [ ] Журнал: баннер вместо «Бот удалён» в каждой строке, пробные скрыты, «перезвонили» внутри пропуска, строки ≈ 48 px.
- [ ] Остальная админка MikoPBX не изменилась (стили только внутри `.module-messenger-hub`).
- [ ] Нет горизонтальной прокрутки на 1024 px (кроме таблицы журнала в своём контейнере).
- [ ] Все тексты — в файлах переводов.
