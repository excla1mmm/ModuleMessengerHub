Правки по скриншотам 20 ноября

Что видно в работающем модуле и как поправить. CSS — в mh-theme.css, слой «v4: посадка в админку MikoPBX».

№ЭкранСейчасПравкаCSS / класс
1ВездеТекст 15–16 px с разрядкой, мельче 11 px — выбивается из админки (база Fomantic 14 px)Основной текст 14/20, подписи 12/16, letter-spacing: 0. Заголовок вкладки внутри модуля — 20 px, не больше заголовка страницы (28 px)--mh-text-body: 14px; --mh-text-caption: 12px; letter-spacing: 0
2ВездеКнопки разной высоты: «Отмена» 36, «Далее» 38, «Назад» 36Все кнопки — 32 px, как в админке. Порядок: слева «Назад», справа «Отмена» (текстом) и главная кнопка--mh-control-m: 32px; .mh-actions
3ВездеПереключатель «Модуль включен» синий, наши — оранжевые: на одном экране два вида тумблеровОставить оранжевый для главной кнопки и активной вкладки; тумблеры модуля — как у админки (синий). Либо переопределить и шапку — решает бренд MIKO.module-messenger-hub .ui.toggle.checkbox.checked .mh-track { background: #2185d0 }
4Уведомления · пустоПустой список с «Новое уведомление», хотя бота ещё нет — мастер упрётся в шаг 3Первый запуск — два шага: «Подключите мессенджер» (выбор Telegram / MAX) → «Создайте уведомление» (заблокирован до шага 1).mh-onboard
5Уведомления · списокКнопка «Новое уведомление» только в пустом состоянииВ непустом списке — справа на одной линии с вкладками—
6Шаг 1Два заголовка подряд: «Новое уведомление» и «О чём сообщать?»Один заголовок «О чём сообщать?», под ним шаги—
7Шаг 1Сетка на 3 колонки с пустыми местами; «Далее» активна без выбораgrid auto-fill minmax(260px, 1fr); карточка выделяется рамкой; «Далее» неактивна, пока ничего не выбрано.mh-scenario-grid, .mh-scenario.is-selected
8Шаг 2«Сотрудники: Нет доступных вариантов» — пустой справочник выглядит как готовое значениеПлейсхолдер «Все сотрудники». Не загрузились — красная подсказка с «Повторить», поле не блокируем.field.error .mh-help
9Шаг 2Направление — чекбоксы в рамке на всю ширину; подсказка «Если ничего не выбрано…» внизу формыСегментированный выбор в одну строку; подсказка «Пустое поле — подходят все» — над полями.mh-seg
10Шаг 2Заголовок «Удалять сообщение…» повторяет подпись тумблераТолько подпись тумблера и одна строка пояснения—
11Шаг 2–3Поля растянуты на 930 pxКолонка формы максимум 560 px, справа — предпросмотр или итог.mh-form-col { max-width: 560px }
12Шаг 3Нет сводки перед созданиемБлок «Итог» одной фразой + «Отправить пример себе»; главная кнопка — «Создать уведомление», а не «Далее»—
13Журнал«Бот удалён» текстом в каждой строке — проблема не виднаКрасный баннер над таблицей с причиной и кнопкой «Подключить бота»; в строке — красная метка «Не доставлено».ui.negative.message
14ЖурналМетка «проба» отдельной строкой — каждая строка 86 pxПробные скрыты по умолчанию (чекбокс «Показывать пробные»); если видны — метка в той же строке. Строка ≈ 48 px.mh-probe
15Журнал«Клиенту перезвонили» — отдельные события-шумПоле «Перезвонили в 18:44» в карточке пропуска; отдельной строкой не показывать—
16ЖурналПропущенный звонок — «Предупреждение»: жёлтые метки на половине экранаПропуск — «Инфо» (без метки). Жёлтое — только то, что требует действия—
17ЖурналВ карточке технические поля (core.missed_call, ID) и «Бот удалён» дважды на получателяТехнические детали свернуть; на получателя одна строка: кто — статус — причина. «Повторить» — только если повтор возможен—
18ЖурналЧетыре фильтра, из них «источник» и «важность» почти не нужныПериод · Событие · Отправка (доставлено / не доставлено)—
19Настройки«Добавить бота →» — текстовая ссылка; MAX — заглушка «скоро», хотя он уже работаетДве равные карточки Telegram и MAX с кнопками «Подключить Telegram» / «Подключить MAX»; заглушку убрать—
20НастройкиОранжевый блок предупреждения о данных — самый заметный элемент экранаНейтральная плашка в одну строку внизу раздела «Общие»; адрес АТС — первым полем—
