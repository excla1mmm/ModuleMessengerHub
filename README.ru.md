# Уведомления в мессенджеры (ModuleMessengerHub)

[English version](README.md)

Модуль MikoPBX, который сам собирает события АТС и установленных модулей и присылает уведомления
в **Telegram** и **MAX**.

> **Статус: этапы 2 (Telegram) и 3 (MAX) приняты на тестовой станции (20–21.11.2026).** Боты,
> поиск чатов, правила, журнал событий, надёжная доставка, удаление после перезвона и канал MAX
> (включая TLS с сертификатом НУЦ Минцифры) реализованы и проверены живым ботом и реальными чатами.
> План и этапы — в каталоге [`Plan/`](Plan/README.md).

## Что уже умеет модуль

- **Подключение бота Telegram или MAX** по токену, проверка токена, поиск чатов («Подключить чат»),
  тестовое сообщение через ту же очередь, что и реальные уведомления.
- **Сбор событий** АТС и установленных модулей MIKO: пропущенный звонок, провайдер недоступен/доступен,
  системные предупреждения, голосовая почта; клиент не дождался в очереди, звонок в нерабочее время,
  звонок с парковки не забрали; звонок, требующий внимания (ИИ Супервайзер), заявка на
  перезвон и отключившиеся воркеры (VoiceAgent); смена состояния модулей (воркеры и очередь распознавания
  речи, инциденты облачного распознавания, паузы облачного ИИ); события безопасности — подозрение на
  мошеннический звонок (опасное международное направление, всплеск исходящих внешних звонков, звонок в
  нерабочее время), новое устройство у сотрудника и подбор пароля SIP.
- **События конфигурации и инфраструктуры АТС**: изменения настроек (одно сообщение о том, какие
  разделы менялись: маршрутизация, провайдеры, номера, файрвол, ключи API, модули и т. д. — без
  значений полей), смена внешнего IP-адреса и напоминания об истечении лицензии за 14/7/1 день
  и после её окончания. Пороги (пауза объединения изменений, частота проверки IP и лицензии, список
  дней напоминания) настраиваются на вкладке «Настройки».
- **Правила («Уведомления»)**: сценарий (тип события), условия (сотрудники, направление звонка,
  провайдеры, оценка качества) и получатели — выбранные чаты, личный чат сотрудника или
  «сотруднику, иначе в общий чат».
- **Надёжная доставка**: очередь в SQLite и воркер доставки, повторы с задержкой, лимиты каналов
  (Telegram и MAX), 429 `retry_after`, возврат зависших аренд, защита от дублей (одно сообщение на
  событие и чат), кнопка «Открыть звонок», маскирование номера.
- **Удаление уведомления, если клиенту перезвонили** (пропущенный звонок): если в течение окна правила
  (по умолчанию 20 минут) состоялся отвеченный звонок с тем же номером клиента, бот либо вовсе не
  отправляет сообщение из очереди, либо удаляет уже отправленное вместе с вложениями. В журнале
  статусы «Не отправлено — перезвонили» / «Удалено — перезвонили» / «Не удалось удалить» с временем
  и сотрудником.
- **Журнал («Журнал»)**: каждое событие с отправками по чатам, статусами, кодами ошибок, действием
  «Повторить» для неудачных отправок и отметками о перезвоне.

Модуль не меняет ядро MikoPBX и другие модули: он только читает их данные.

## Как подключить бота Telegram (администратор)

1. Создайте бота в Telegram через **@BotFather** (`/newbot`) и скопируйте токен.
2. Откройте модуль: **Настройки → Мессенджеры → Telegram → Добавить бота**, вставьте токен и нажмите
   **Проверить**. При неверном токене показывается понятная ошибка, токен не сохраняется.
3. **Подключите чаты**: нажмите **Подключить чат** и в течение пяти минут либо добавьте бота в
   группу/канал, либо откройте личный чат с ботом и нажмите **Start** (отправьте любое сообщение).
   Найденные чаты появятся в карточке бота — включите нужные.
4. Для личных уведомлений привяжите личный чат к сотруднику и выберите в правиле получателя
   «сотрудник» (или «сотрудник, иначе в общий чат»).
5. Нажмите **Отправить тест** — сообщение уйдёт через очередь доставки, результат виден по каждому чату.
6. Создайте уведомление в разделе **Уведомления** (сценарий → условия → куда отправлять).
7. Для сценария «Пропущенный звонок» включите **«Удалять сообщение, если клиенту перезвонили»**,
   задайте окно (5–120 минут, по умолчанию 20) и решите, считать ли перезвоном дозвон клиента.

Для удаления сообщений Telegram требует, чтобы бот был **администратором группы/канала** с правом
удаления сообщений. Бот, удалённый из чата, помечается «бот удалён из чата», бесконечных повторов нет.

## Как подключить бота MAX (администратор)

Шаги проверены на тестовой станции с реальным ботом MAX 21.11.2026.

1. Владелец организации создаёт бота на **business.max.ru** (раздел «Чат-боты») от имени
   верифицированного профиля организации, ИП или самозанятого. Профиль проходит модерацию
   (до 48 часов в рабочие дни); токен появляется после неё.
2. Откройте модуль: **Настройки → Мессенджеры → MAX → Добавить бота**, вставьте токен и нажмите
   **Проверить**. Показывается имя бота; при неверном токене — понятная ошибка, токен не сохраняется.
3. **Подключите чат** двойным нажатием **Подключить чат** и в течение пяти минут либо нажмите
   **«Начать»** в диалоге с ботом, либо добавьте бота в группу/канал. Найденные чаты появятся в
   карточке бота — включите нужные. Название группы подставляется из MAX (если доступно), иначе его
   можно задать вручную.
4. Нажмите **Отправить тест** и создайте уведомление так же, как для Telegram.
5. Если MAX отвечает, что подписка на обновления (вебхук) блокирует поиск чатов, снимите её запросом
   `DELETE /subscriptions` и повторите поиск.
6. Если в карточке бота появилось «Не удалось проверить сертификат MAX», значит АТС не доверяет
   корневому сертификату НУЦ Минцифры. Модуль поставляет его сам (`Russian Trusted Root CA`,
   отпечаток закреплён); при необходимости укажите свой файл в настройке `max_ca_bundle_path`.
   Проверка TLS никогда не отключается.

Для удаления сообщений в группе MAX бот должен быть **администратором с правом удаления**. Срок,
после которого MAX не даёт удалить сообщение, в документации не указан и на тестовом боте не выяснен
(сообщений старше суток там нет) — модуль честно предупреждает об этом в подсказке правила.
Если бота удалили из группы, MAX отвечает `error.not.found`, если пользователь заблокировал бота —
`chat.denied`: в обоих случаях чат помечается «бот удалён из чата» без бесконечных повторов.

## Требования

- MikoPBX 2025.1.1 или новее.
- Исходящий HTTPS-доступ АТС к `api.telegram.org` и `platform-api2.max.ru` (напрямую или через прокси,
  заданный в настройках модуля).
- Токен бота Telegram от @BotFather и/или токен бота MAX с business.max.ru.

## Безопасность и персональные данные

Номера телефонов, имена сотрудников и тексты событий передаются во внешний мессенджер. Уведомления
по умолчанию выключены; номер можно маскировать, вложения — отключать. Токены ботов хранятся только на
АТС, не возвращаются API (показывается лишь короткая подсказка) и не попадают в логи и коды ошибок.
Для опроса источников хаб использует собственный ключ API только на чтение.

Модуль поставляет корневой сертификат `Russian Trusted Root CA` (НУЦ Минцифры) только для проверки
`platform-api2.max.ru`; для других соединений он не используется, проверка TLS никогда не отключается:

- файл: `Lib/Channels/Max/certs/russian_trusted_ca.pem`
- отпечаток SHA-256: `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`
  (проверка: `openssl x509 -noout -fingerprint -sha256 -in Lib/Channels/Max/certs/russian_trusted_ca.pem`)
- источник: https://gu-st.ru/content/Other/doc/russiantrustedca.pem (официальная выдача НУЦ Минцифры)

Об уязвимостях: см. [`SECURITY.md`](SECURITY.md).
