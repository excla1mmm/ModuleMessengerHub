# 10. Тестирование

## Контрактные тесты (локально и в CI)

`php Tests/run-all.php` запускает все `Tests/check-*.php`. Каждый проверочный скрипт — отдельный процесс,
выход с ненулевым кодом = провал. Ядро MikoPBX локально не запускается: нужные классы ядра подменяются
минимальными заглушками в `Tests/fixtures/core/` (как в ModuleAISupervisor).

Обязательные группы проверок по мере появления кода:

| Группа | Что проверяет |
|---|---|
| skeleton | `module.json`, регистрационные ключи во всех 29 `Messages/*.php`, каталоги — самостоятельные массивы, `php -l` всех PHP |
| secrets | токен не попадает в ответы REST, логи, `last_error_code`, исключения `HttpTransport` |
| channels | разбор ответов Telegram/MAX по записанным фикстурам: успех, 429/`retry_after`, 403 blocked/kicked, `migrate_to_chat_id`, `attachment.not.ready`, HTTP 200 + `success:false` |
| outbox | UNIQUE(event, recipient), лизинг, протухший лизинг, `RetryPolicy`, `stale` для `info` |
| sources | дедупликация, курсоры, «история не рассылается», недоступный модуль-источник |
| missed-call | правила «пропущенного» на фикстурах CDR (одно плечо ответило → не пропущенный) |
| rendering | экранирование HTML/markdown, обрезка под лимит канала, маскирование номера |

SQLite-тесты — на временной базе (`:memory:` или файл в `sys_get_temp_dir()`), схема из моделей.

## Мок-серверы мессенджеров

`Tests/fixtures/telegram/*.json`, `Tests/fixtures/max/*.json` — реальные (обезличенные) ответы API.
`HttpTransport` принимает подменяемый базовый URL, чтобы тесты шли на `php -S` мок без сети.

## Тестовая станция

Локального Docker нет. Проверка на тестовой станции MikoPBX (доступ — в `LOCAL.md`, его нет в git):
сборка `VERSION=1.<n> ./scripts/package-module.sh <dir>`, загрузка `files:upload`, установка
`modules:installFromPackage`, проверка `m_PbxExtensionModules`. Для проверок кода — PHP CLI-скрипт с
`require_once 'Globals.php';`, весь скрипт в `try/catch` (необработанное исключение отключает модуль).

Боевые проверки каналов — на тестовых ботах Telegram и MAX (MAX-бот требует верифицированного профиля
организации MIKO; оформить заранее, модерация до 48 ч).

## Ручной сценарий приёмки этапа 1

1. Подключить бота Telegram и бота MAX.
2. Подключить группу и личный диалог в каждом.
3. Отправить тест — проверить все 4 чата.
4. Отключить интернет на станции на 5 минут, отправить тест — после восстановления сообщения дошли.
5. Удалить бота из группы — тест в группу помечает получателя `gone`.
6. Поискать токен в `log/ModuleMessengerHub/*`, ответах `/bots`, истории — не найден.
