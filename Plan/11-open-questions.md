# 11. Открытые вопросы и решения

Формат: вопрос → что известно → что нужно сделать. Решённое переносить в раздел «Решения» с датой.

## Открытые

**Q1. Ключ API для чтения REST модулей-источников без изменений ядра.**
Известно: ModuleLocalSpeechToText создаёт ключи через модель ядра `MikoPBX\Common\Models\ApiKeys` и
`TokenValidationService` (`Setup/PbxExtensionSetup.php`, `reconcileStoredWorkerApiKeys`). Нужно: проверить,
можно ли хабу при установке создать собственный ключ с правами только на чтение конкретных путей
(`allowed_paths`/группы прав v3), как он хранится (хэш) и как воркер хаба его использует; что видит
администратор в списке ключей. Использование модели ядра — не изменение ядра.

**Q2. AMI-подключение воркера.** Как воркеры модулей подключаются к AMI на целевой версии
(учётка менеджера, `generateManagerConf`, помощники ядра) — взять из опубликованного эталонного модуля
с AMI-воркером (github.com/mikopbx) и из ModuleTelegramNotify (у него AMI `CdrConnector`).

**Q3. Вход в систему без изменения ядра.** Проверить на станции, что видит хук `onAfterExecuteRestAPIRoute`
для `auth:login` (маршрут, код ответа, пользователь, IP). Если недостаточно — чтение syslog с курсором
(путь лога зависит от окружения: железо/Docker).

**Q4. ModuleNotifier и ModuleTelegramNotify (MIKO).** Уже отправляют уведомления о звонках в Telegram
(Notifier — ещё и VK). Решить: хаб заменяет их (миграция настроек/инструкция) или сосуществует
(тогда в README — чем отличаются). Не делать миграцию их данных без решения владельцев.

**Q5. Связь с `moduleaisupervisor#10`.** По принципу pull задача #10 реализуется в хабе источником
`ai_supervisor.attention_call` + шаблоном по клиентскому ТЗ; ИИ Супервайзер не меняется. Нужно решение:
переписать #10 как «реализовать в ModuleMessengerHub» или закрыть со ссылкой на задачу хаба.
Учесть сроки клиента: этапы 1–3 хаба против одной функции.

**Q6. Каталог сторонних источников.** Для ModuleBackup, ModuleGetSsl, ModuleVPN, ModuleAmoCrm,
ModuleBitrix24Integration, ModuleRemoteSupport, ModuleQueueCallBack — проверить, есть ли у них
читаемый API со статусами/ошибками. Без API источник не делаем.

**Q7. Конвертация записей.** Есть ли на АТС `ffmpeg`/`sox` для `webm → mp3` (железо, Docker, ARM).
Если нет — вложения только в исходном формате и только для каналов, которые его принимают.

**Q8. Тестовый бот MAX.** Нужен верифицированный профиль организации MIKO на business.max.ru и
прошедший модерацию бот — оформить до начала этапа 1.

**Q9. Коды ошибок MAX** «бот удалён из чата», «пользователь заблокировал бота», права бота в группе,
может ли бот писать первым — выяснить на тестовом боте, дополнить `03-channels.md`.
