# 08. Надёжность

## Идемпотентность

- `Events.dedupe_key` UNIQUE: повторный опрос, повторный AMI-эвент, перезапуск воркера не создают дубль.
- `Outbox(event_id, recipient_id)` UNIQUE: одно сообщение одному получателю.
- Отправка «ровно один раз» в мессенджер невозможна (ответ может потеряться после доставки). Принимаем
  «не более одного повтора при неизвестном исходе»: при таймауте после отправки строка получает
  `retry` с флагом `uncertain`; второй неизвестный исход → `failed` без дальнейших попыток.

## Лизинг и повторы

- Delivery берёт пачку строк `pending` с `next_attempt_at <= now`, ставит `sending` + `lease_until`
  (атомарно, UPDATE … WHERE status/lease). Протухший лизинг возвращается в `pending`.
- `RetryPolicy`: 10 с, 30 с, 2 мин, 10 мин, 30 мин, 2 ч; затем `failed`. `retry_after` канала важнее.
- `recipient_gone` → получатель `state=gone`, строки к нему `dropped`, в истории видна причина.
- `permanent` (неверный токен, некорректный запрос) → `failed`, бот помечается ошибкой, без повторов.

## Лимиты каналов

`RateLimiter` на (бот, чат) и на бота в целом по `ChannelLimits`:
Telegram ~1/с на чат, ~20/мин на группу, ~30/с на бота; MAX ≤ 2/с на чат, ≤ 30 rps суммарно.
Превышение — строка откладывается, а не отправляется с ошибкой.

## Деградация

- Мессенджер недоступен: строки копятся, отправляются после восстановления; события не теряются.
- Очередь старше 24 ч для типа `info` — `dropped` с причиной `stale` (пропущенный звонок недельной давности
  никому не нужен); `warning`/`critical` — доставляются.
- Поток событий (например, массовые пропущенные при аварии): ограничение N сообщений в минуту на получателя,
  остаток — одним сводным сообщением «и ещё K событий» (этап 4; в v1 — только лимит).
- Источник падает — `availability=error`, повтор опроса с растущим интервалом, остальные источники работают.

## Нагрузка на АТС

- Хуки ядра — только запись строки/пинок трубы, без сетевых вызовов.
- Опрос REST API источников — с интервалами (по умолчанию 30–60 с), лёгкими запросами (лимит, курсор).
- Очистка истории — батчами в cron, не в момент установки/включения.
- Установка/обновление модуля не трогает историю (урок `modulelocalspeechtotext#5`).

## Наблюдаемость

Свой структурированный лог модуля (`log/ModuleMessengerHub/`): события `source.poll_failed`,
`delivery.failed`, `bot.check_failed` — с кодами, без токенов и без текстов сообщений.
