# 12. Удаление уведомления о пропущенном, если клиенту перезвонили

Запрос пользователя 19.11.2026. Этап 2 (Telegram), для MAX — этап 3.

## Что нужно

В уведомлении (правиле) о пропущенных звонках — опция
**«Удалять сообщение, если клиенту перезвонили в течение 20 минут»**.
Если в течение этого времени клиенту перезвонили, бот удаляет уже отправленное сообщение о пропущенном
во всех чатах, куда оно ушло. Если сообщение ещё не отправлено (стоит в очереди), оно не отправляется.

Смысл: в чате остаются только те пропущенные, по которым клиенту так и не перезвонили.

## Поведение

1. Опция доступна только для сценария «Пропущенный звонок» (`core.missed_call`). В будущем — для заявок
   на перезвон VoiceAgent, тем же механизмом.
2. Окно — 20 минут по умолчанию, настраивается в правиле: 5–120 минут. Отсчёт — от окончания пропущенного звонка.
3. **«Перезвонили»** = состоялся **отвеченный** звонок с тем же номером клиента после пропущенного и в пределах окна:
   - исходящий звонок с АТС на номер клиента, на который ответили, — всегда;
   - входящий звонок от этого клиента, на который ответили (клиент дозвонился сам), — тоже считается
     (переключатель в правиле, по умолчанию включён: проблема клиента в любом случае решена).
4. Номера сравниваются нормализованно: только цифры, последние 10 (`+7 968 968-94-44` = `89689689444`).
5. Удаляются **все** сообщения этой отправки: текст и отдельные сообщения с записью или фрагментами.
6. В журнале событие пропущенного остаётся. В карточке события — отметка: «Сообщение удалено: клиенту
   перезвонили в 15:52 (Иванов И., 233)» или «Не отправлено: клиенту перезвонили до отправки».
7. Если удалить не удалось (бот удалён из чата, мессенджер недоступен дольше лимита, сообщение старше лимита
   мессенджера) — отметка «Не удалось удалить» с кодом; сообщение остаётся в чате, повторы — по общей политике.

## Откуда хаб узнаёт о перезвоне

Тот же поток, что и для пропущенных: AMI `UserEvent CdrConnector` (`action=hangup_update_cdr`). Сейчас
`MissedCallSource` отбрасывает отвеченные звонки. Нужно:

- для каждого завершённого звонка с `GLOBAL_STATUS = ANSWERED` извлечь номер клиента (внешняя сторона по карте
  внутренних номеров) и направление;
- если по этому номеру есть пропущенный в пределах самого большого окна среди правил — записать событие
  `core.missed_call_resolved`: `dedupe_key = resolved:{missed_linkedid}`, payload — `missed_linkedid`,
  `resolved_linkedid`, время, направление, сотрудник (из карты), номер;
- индекс «номер клиента → последний пропущенный за 120 минут» держать ограниченным (в памяти AMI-воркера
  с восстановлением из журнала событий при старте, или запросом к `m_MessengerHubEvents` по
  нормализованному номеру — выбрать при реализации, индекс по номеру обязателен).

Ядро и модули-источники не меняются.

## Доставка

- Router, получив `core.missed_call_resolved`, находит отправки исходного пропущенного (по `missed_linkedid`)
  в правилах с включённой опцией, где окно ещё не истекло:
  - отправка в очереди (`pending`) → `cancelled` с причиной `resolved_before_send`;
  - отправка доставлена (`sent`) → задача удаления по каждому `external_message_id`.
- В `m_MessengerHubOutbox` хранить **все** `external_message_id` отправки (текст + вложения), а не один.
- Новые статусы отправки: `cancelled`, `retracted`, `retract_failed`.
- Удаление идёт через ту же очередь с повторами и лимитами канала (Plan/08).

### Каналы

| Канал | Метод | Ограничения (сверить с документацией перед реализацией) |
|---|---|---|
| Telegram | `deleteMessage(chat_id, message_id)` | бот удаляет свои сообщения не старше 48 часов; в каналах нужны права администратора на удаление |
| MAX | удаление сообщения бота (`DELETE /messages` с `message_id`) | наличие метода, лимит по возрасту и ошибки — проверить на тестовом боте MAX |

`ChannelInterface` дополняется методом `delete(BotCredentials, Recipient, string $externalMessageId): SendResult`.

## API (без новых ресурсов)

- `rules` — в `options` правила:
  `retract_on_callback: {enabled: bool, window_min: 20, count_incoming_answered: true}`.
- `events` — в `deliveries[]` события: статусы `cancelled`, `retracted`, `retract_failed`, поле `retract_reason`,
  `resolved_at`, `resolved_by` (сотрудник).

## Интерфейс

- Мастер «Новое уведомление», шаг «Условия» сценария «Пропущенный звонок»: переключатель
  «Удалять сообщение, если клиенту перезвонили в течение [20] минут» и вложенный
  «Считать перезвоном и дозвон клиента», подсказка: «В чате останутся только пропущенные, по которым
  не перезвонили».
- Строка уведомления в списке: «… · удалять при перезвоне за 20 мин».
- Журнал: статус отправки «Удалено — перезвонили» / «Не отправлено — перезвонили».

## Критерии приёмки — проверены 20.11.2026 (пробы через штатный вход AMI-воркера, живых звонков на
станции нет; реальное удаление в тестовой группе и в личном чате):

- [x] Пропущенный → сообщение в чате → исходящий отвеченный звонок клиенту через 10 минут → сообщение
      удалено во всех чатах (вместе с записью), в журнале отметка с временем и сотрудником.
      **Проба на станции (2e):** проба события 78 дала две отправки — личный чат и группа; отвеченный
      перезвон через ~11 минут → обе строки `retracted`, сообщения 14 и 25 удалены в Telegram,
      `resolved_by = «Портнов Алексей (204)»`, `resolved_at` заполнен. Вложения появятся на этапе 3а;
      механизм удаляет все сохранённые `external_message_id` (текст + каждое вложение).
- [x] Перезвон через 25 минут при окне 20 → сообщение остаётся. **Проба на станции (2d):** resolved-событие
      записано, строка осталась `sent`, `retract_requested_at` пуст (окно 1200 с).
- [x] Перезвон без ответа клиента (NOANSWER) → сообщение остаётся. **Проба на станции (2d):** событие
      `core.missed_call_resolved` не создаётся, строка `sent`.
- [x] Клиент дозвонился сам и ему ответили → удаляется (если включено «Считать дозвон клиента»), иначе
      остаётся. **Проба на станции (2d):** при включённом флаге входящий отвеченный → `retracted`;
      при выключенном — две строки остались `sent`, resolved-событие при этом записано в журнал.
- [x] Перезвон раньше, чем сообщение ушло из очереди → сообщение не отправляется. **Проба на станции
      (2d):** воркер доставки приостановлен на время пары, затем оба события обработаны одним проходом →
      строка `cancelled`, `resolved_before_send`, `external_message_ids` пуст.
- [x] Номер в другом формате (`+7…` / `8…`) распознаётся. **Проба:** пропущенный `+7 968 968-94-44`,
      перезвоны `89689689444` и `+79689689444` — сопоставление по последним 10 цифрам сработало
      (2d и 2e); юнит `Tests/check-retraction.php`.
- [x] Удаление недоступно (бот удалён из чата) → «Не удалось удалить», без бесконечных повторов.
      **Проба + юнит:** `telegram.403.kicked` → `retract_failed`, `retract_attempts=1`, повторов нет;
      удалённая запись бота/чата → `retract_failed / bot_deleted` без вызова канала
      (`Tests/check-retraction.php`).
- [x] Правило без опции → ничего не удаляется. **Юнит:** `Tests/check-retraction.php` — строка остаётся
      `sent`, запроса удаления нет; в 2e правило без опции не создавалось.


## Реализация этапа 2d (20.11.2026)

- **Детектор** — `MissedCallSource`: завершённый `CdrConnector`-звонок с `ANSWERED` даёт «клиента»
  (внешняя сторона по карте внутренних номеров) и направление; индекс «номер → недавние пропущенные»
  (последние 10 цифр, окно 120 мин, до 500 записей) наполняется при записи пропущенного и
  восстанавливается при старте AMI-воркера из журнала (`RecentMissedLoader`). На каждый недавний
  пропущенный с тем же номером пишется `core.missed_call_resolved`, `dedupe_key = resolved:<missed_linkedid>`.
- **Планировщик** — `RetractionPlanner` (в Router): по `rule_id` каждой отправки исходного пропущенного
  проверяет `retract_on_callback.enabled`, окно правила (5–120 мин от конца пропущенного) и
  `count_incoming_answered`; `pending` → `cancelled`, `sent`/`sending` → запрос удаления.
- **Удаление** — `RetractionService` в воркере доставки: `deleteMessage` по каждому
  `external_message_id` (текст и вложения), лимиты канала, `RetryPolicy`, `retry_after`; `403`/`400`
  → `retract_failed` без повторов, исчезнувший бот/чат → `retract_failed / bot_deleted`.
- Статусы и отметки — в `deliveries[]` и журнале; проба события помечается в журнале и в сообщении.
- Тесты: `Tests/check-retraction.php` покрывает все критерии приёмки.

## Открытые вопросы

- Удалять или **редактировать** сообщение («✅ Перезвонили в 15:52, Иванов») — по запросу удаляем; редактирование
  можно добавить как второй режим опции, если руководителям нужна история в чате.
- Пропущенный в очередь/группу: перезвонил любой сотрудник — считается (по запросу: «клиенту перезвонили»).
