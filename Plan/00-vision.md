# 00. Цель и принципы

## Цель

Руководитель и администратор узнают о важном сразу в мессенджере, не заходя в АТС:
пропущенный звонок, упавший провайдер, звонок, который ИИ отметил как требующий внимания,
заявка на перезвон от голосового агента, отключившийся воркер и т. п.

Первая версия: подключение ботов **Telegram** и **MAX**, получатели, правила, надёжная отправка.
Дальше — расширение каталога источников и каналов.

## Принципы (нарушать нельзя)

1. **Ядро MikoPBX не меняется.** Ни правок, ни патчей, ни подмены файлов ядра. Хаб использует только то,
   что ядро уже предоставляет модулям: хуки `ConfigClass`, AMI, REST API v3, свои воркеры и cron.
2. **Pull-модель.** Хаб сам забирает данные. Модули-источники про хаб не знают, ничего ему не отправляют
   и не меняются ради него. Хаб читает их **публичные** интерфейсы (REST API v3, ленты событий),
   а не их внутренние таблицы и классы.
3. **Источник недоступен — хаб не ломается.** Модуль не установлен, выключен, сменил версию API —
   источник помечается недоступным, остальные работают.
4. **Одно событие — одно сообщение получателю.** Повторный опрос, перезапуск воркера, повторная отправка
   не дают дублей. Идемпотентность по ключу события.
5. **Хаб не тормозит АТС.** Хуки, которые вызывает ядро, только записывают факт и сразу возвращают
   управление. Вся работа — в воркерах модуля.
6. **Секреты не утекают.** Токены ботов не возвращаются REST API, не пишутся в логи, не попадают в тексты ошибок.
7. **Персональные данные — осознанно.** Номера, тексты, записи уходят во внешний мессенджер только после
   явного включения; маскирование номера и отключение вложений доступны.
8. **Каналы и источники — плагины.** Новый мессенджер или источник добавляется классом-адаптером,
   без переделки очереди, правил и интерфейса.

## Что не входит в первую версию

- Действия из мессенджера (кнопки «взять в работу», команды боту) — требуют постоянного приёма апдейтов.
- Вебхуки от мессенджеров (у АТС обычно нет публичного HTTPS).
- Почта, VK, Bitrix24-чат, Slack — каналы следующих версий.
- Сводки за период (дайджесты) — этап 4.
